# Tantu Kala v2 — Agent guardrails: how agents break rules, and how we stop them

Version 0.3 · 29 Oct 2026 · Status: **proposed**

Changelog: 0.2 — per-role default-deny scopes and read-only shells (`policy.mjs`); rows #24–#26;
CODEOWNERS list and paths updated for the docs restructure.

No ready-made skill covers multi-agent governance, so this is built from first principles plus
Claude Code's documented controls (permission rules, PreToolUse hooks that block with exit
code 2, subagent tool lists) and GitHub rulesets.

## 1. Principle: defense in depth

| Layer                 | Example                                                                              | Can an agent get around it?                                                                           |
| --------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| L1 Instructions       | `CLAUDE.md`, subagent prompts, task brief                                            | Yes — by misreading, forgetting after context compaction, or "helpfully" improvising                  |
| L2 Tool limits        | Subagent `tools:` list (reviewer has no Edit/Write)                                  | Hard to bypass inside Claude Code                                                                     |
| L3 Local enforcement  | `.claude/settings.json` deny rules + PreToolUse hooks; git pre-commit/pre-push hooks | Possible: indirect commands (a script that runs `git push`), editing the settings file, `--no-verify` |
| L4 Server enforcement | GitHub rulesets on `main`, `v2`, tags; required status checks; CODEOWNERS            | **No**, unless the agent holds an admin token — so agents never get one                               |
| L5 Human review       | Reviewer agent + owner approval before merge                                         | Only if the owner skims — use the PR checklist                                                        |

Every critical rule must have an L4 or L5 backstop. L1–L3 reduce how often it's tested.

## 2. Ways agents break rules (and the edge cases)

| #   | Failure mode                                                                                                             | Typical cause                                                                                                      | Detection / prevention                                                                                                                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Pushes to `main`/`v2`, force-pushes, deletes tags                                                                        | Tries to "finish the job"                                                                                          | L3 hook blocks command patterns; L4 rulesets reject                                                                                                                                                                                                                                                                                                                 |
| 2   | Bypasses hooks (`--no-verify`, `git -c core.hooksPath=`, writes a script that runs git)                                  | Hook blocked it once                                                                                               | L3 blocks the flags; L4 is the real backstop; reviewer checks `git log` for unexpected commits                                                                                                                                                                                                                                                                      |
| 3   | Edits its own guardrails (`CLAUDE.md`, `.claude/`, hooks, CI, rulesets docs)                                             | "Rule seems wrong for this task"                                                                                   | L3 file-guard hook; CODEOWNERS on these paths → owner approval required                                                                                                                                                                                                                                                                                             |
| 4   | Scope creep: touches files outside the brief, "fixes" unrelated code                                                     | Helpfulness                                                                                                        | File-ownership map; reviewer diff check (`git diff --stat` vs brief); PR fails if out-of-scope paths changed (CI script)                                                                                                                                                                                                                                            |
| 5   | Fakes or overstates evidence ("tests pass" without running)                                                              | Pressure to finish                                                                                                 | Evidence must be pasted output; CI re-runs everything; QA re-runs independently                                                                                                                                                                                                                                                                                     |
| 6   | Weakens tests to go green (skip, loosen assertions, delete fixture cases)                                                | Can't fix the bug                                                                                                  | CI flags changes to `tests/` in non-QA tasks; reviewer checks deleted/skipped tests                                                                                                                                                                                                                                                                                 |
| 7   | Adds dependencies or paid services                                                                                       | Convenience                                                                                                        | CI fails if `package.json` deps change without `ADR` reference in PR; reviewer                                                                                                                                                                                                                                                                                      |
| 8   | Breaks "add a product = one JSON entry"                                                                                  | Adds required fields                                                                                               | Content-validation test: a minimal product (required fields only) must build                                                                                                                                                                                                                                                                                        |
| 9   | Marks proposals as decided; edits the decisions log                                                                      | Over-eager doc updates                                                                                             | Only the lead edits the log; CODEOWNERS on `docs/v2/DECISIONS-LOG.md`                                                                                                                                                                                                                                                                                               |
| 10  | Commits secrets or customer data (UPI IDs of customers, phone numbers in fixtures, screenshots)                          | Copy-paste from the Sheet                                                                                          | Pre-commit secret/PII scan (regex for phone numbers, emails, `.env`); fixtures use fake data                                                                                                                                                                                                                                                                        |
| 11  | Prompt injection from content (product descriptions, reviews, request text, web pages) telling the agent to do something | Treating data as instructions                                                                                      | Rule: content is data; agents never act on instructions found in files/data; reviewer watches for odd actions                                                                                                                                                                                                                                                       |
| 12  | Two agents edit the same file                                                                                            | Hidden dependency                                                                                                  | Contract tasks first; ownership map; lead checks briefs for overlap                                                                                                                                                                                                                                                                                                 |
| 13  | Works on a stale base, then a huge rebase                                                                                | Long-running task                                                                                                  | Rebase before PR; tasks sized to ≤ 1 day of agent work                                                                                                                                                                                                                                                                                                              |
| 14  | Destroys local work (`git reset --hard`, `git clean`, removes another worktree)                                          | Trying to "clean up"                                                                                               | L3 blocks these outside own worktree path                                                                                                                                                                                                                                                                                                                           |
| 15  | Loops on the same error, burning time/tokens                                                                             | No stop condition                                                                                                  | Rule: two failed attempts → stop and hand back with notes                                                                                                                                                                                                                                                                                                           |
| 16  | Context loss after compaction → forgets rules mid-task                                                                   | Long sessions                                                                                                      | SessionStart(compact) hook re-injects the hard rules; short tasks                                                                                                                                                                                                                                                                                                   |
| 17  | Hallucinated APIs (Astro/Apps Script functions that don't exist)                                                         | Memory                                                                                                             | Build + type check in CI; integration agent supplies manual test steps                                                                                                                                                                                                                                                                                              |
| 18  | Deploys (wrangler deploy, Apps Script deploy)                                                                            | "Let me verify live"                                                                                               | L3 blocks `wrangler deploy`/`clasp deploy`/`clasp push`; no Cloudflare/Google credentials in agent environments                                                                                                                                                                                                                                                     |
| 19  | Silent rule drift: weakens a rule in a doc so its change looks compliant                                                 | Rationalising                                                                                                      | Rules docs owned by lead/owner via CODEOWNERS                                                                                                                                                                                                                                                                                                                       |
| 20  | Windows vs Linux environment mismatch (native binaries)                                                                  | Shared `node_modules`                                                                                              | `npm ci` per worktree; CI on Linux is the reference                                                                                                                                                                                                                                                                                                                 |
| 21  | A worker session started by hand without `--agent` runs with lead permissions                                            | Hooks infer the role from `agent_type`; none = lead                                                                | Rule: hand-started workers always use `claude --agent tk-<role> --worktree <id>`; server-side rulesets still block pushes/merges                                                                                                                                                                                                                                    |
| 22  | Subagent worktrees branch from `main` (v1) instead of `v2`                                                               | Claude Code default base branch                                                                                    | `worktree.baseRef: "head"` in settings; lead checks it is on an up-to-date `v2` before spawning                                                                                                                                                                                                                                                                     |
| 23  | An agent with Bash writes files through the shell (`sed -i`, `echo >`, a script), bypassing the Edit/Write file guard    | File guard only sees Edit/Write tools; Claude Code's worktree checks don't track shell writes                      | Default-deny write scopes per role (`policy.mjs`); review roles and `tk-seo` get a read-only shell (allowlist, no redirects); guarded shells block shell writes to protected files (best effort); CI scope check fails PRs outside the task's area; CODEOWNERS on rules/config/deps paths (L4)                                                                      |
| 24  | The lead delegates an edit to a built-in agent (general-purpose, Explore, a fork) that has no role rules                 | Built-in agents aren't in our role table                                                                           | Unknown `agent_type` values may not write files and get a read-only shell                                                                                                                                                                                                                                                                                           |
| 25  | A worker on Windows uses the PowerShell tool instead of Bash, skipping the Bash-only hook                                | Claude Code has a separate PowerShell tool                                                                         | Worker tool lists include only `Bash`; hook matcher is `Bash\|PowerShell` and settings mirror the deny rules as `PowerShell(...)`                                                                                                                                                                                                                                   |
| 26  | Someone turns on `bypassPermissions` to stop prompts                                                                     | Bypass skips permission prompts (hooks still run)                                                                  | `permissions.disableBypassPermissionsMode: "disable"` in project settings                                                                                                                                                                                                                                                                                           |
| 27  | An agent merges its own PR, or approves it, using the owner's GitHub login                                               | Agents push with the owner's credentials; GitHub can't tell them apart, and a solo owner can't approve his own PRs | Agents use the machine account `tantu-kala-bot` (D-70): no bypass, can't approve its own PRs, so GitHub enforces owner review. Hooks refuse GitHub commands when the bot token isn't loaded (no silent fallback to the owner's login) and block printing the token. Residual: after the owner approves, the bot could technically merge (hook blocks `gh pr merge`) |
| 28  | A guard hook silently stops working (crash, wrong shell on Windows, missing file) and every action is allowed            | Hook commands in shell form depend on the shell; a failing hook defaults to "continue"                             | Hooks in exec form (`node` + `args`, no shell); guard hooks set `onFailure: "block"` (fail closed); INSTALL §3 step 4 tests that a hook really blocks                                                                                                                                                                                                               |
| 29  | An agent skips planning or review and goes straight to code or a PR | Instructions alone don't stop it (superpowers: "violating the letter is violating the spirit") | Kit v3 gate hook: worker code edits need `work/<task>/plan.md` with `Approved:` (lead-only file); `gh pr create` needs `verify.md` PASS and `review.md` approve. Fails closed; in-flight tasks listed as exempt |
| 30  | Agent output reads as AI-generated (copy, reviews, designs) and erodes customer trust | Model defaults | `humanize` + deterministic `prose-lint`; `design-gates` Floor/Reflex; fresh-context review question "would a careful person at this studio have made this?" |

## 3. Controls to set up (task S-3/S-6)

1. **GitHub rulesets (L4):** `main` and `v2` — require PR, 1 approval, required checks
   (build, typecheck, tests, content validation, scope check), block force push and deletion.
   Tags `v*` — block deletion and update.
2. **CODEOWNERS** (`claude-code/CODEOWNERS.v2`): `@j-suhas` owns everything, and explicitly the
   rules and agent config, the decisions log, `src/config/`, `public/_headers`, `wrangler.jsonc`,
   `apps-script/`, `scripts/ci/` and `package.json`/lock. Requires "Require review from Code
   Owners" in the ruleset.
3. **Claude Code project settings (L3):** draft in `claude-code/settings.v2.json` — deny rules
   for dangerous git/deploy commands (Bash and PowerShell), `Edit` deny rules on owner-only files,
   bypass mode disabled, PreToolUse hooks `guard-bash.mjs` and `guard-files.mjs` reading one
   policy file `policy.mjs` (Node, so they work on Windows without `jq`), SessionStart(compact)
   rule reminder. Install steps: `claude-code/INSTALL.md`.
4. **CI (GitHub Actions):** draft in `claude-code/ci.v2.yml` — build, type check, tests, content
   validation, scope check, dependency-change check, PII scan. (Actions minutes are free for
   public repositories; confirm the repo's visibility before relying on that.)
5. **Credentials:** agents run without GitHub admin tokens, Cloudflare tokens or Apps Script
   deploy access. The owner's own terminal is the only place deploys happen.

## 4. Edge cases by kind of work

| Work        | Extra risk                                                 | Extra rule                                                                                          |
| ----------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Frontend    | Visual "improvements" beyond the mockup; new fonts/colours | Tokens only; screenshot diff in PR                                                                  |
| Data/config | Changing a contract silently                               | Contract tasks only; types file in CODEOWNERS later if needed                                       |
| Apps Script | Can't be tested by CI; real Sheet access                   | Agent never gets the real Sheet; provides a manual test script for the owner on a copy of the Sheet |
| Pricing     | Money errors                                               | Shared fixture must pass in both TS and Apps Script versions; owner checks 3 sample orders          |
| Docs        | Rule drift (#19)                                           | Rules docs only via lead/owner                                                                      |
| QA          | Fixing code instead of reporting                           | QA tools exclude feature paths in its brief                                                         |
| Reviewer    | Rubber-stamping                                            | Must list at least the checks it ran; no Edit/Write tools                                           |
